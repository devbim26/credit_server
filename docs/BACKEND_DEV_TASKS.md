# ЗАДАЧА: разобраться в коде сервера списания и согласовать пересылку на внешний сервис

> **Кому:** разработчику бэкенда, который отвечает за внешний сервис
> (devbim.com, эндпоинт `PUT /api/OpenRouterModels/updateSubscription`).
>
> **От кого:** проект «Сервер списания кредитов» (этот репозиторий).
> **Статус:** пересылка НЕ работает — все отчёты отклоняются внешним сервисом с HTTP 404.
> **Дата:** 2026-09-01

---

## 1. Суть проблемы (кратко)

Наш сервер принимает отчёты об использовании ИИ от Open WebUI (пайпы), считает
кредиты и пересылает каждый отчёт на внешний сервис для списания. Пересылка
идёт, но внешний сервис отвечает:

```
HTTP 404
{"...": "Ключ доступа пользователя не был найден"}
```

для UUID `6cce058d-bddf-4c98-96be-bc0494fd32eb`. **Ни одного успешного списания
нет.** Всё видно на дашборде: `http://localhost:4010/dashboard`, вкладка
«③ Отправлено во внешний сервис».

## 2. Что уже проверено (не тратить время)

| Проверка | Результат |
|---|---|
| Пересылка уходит с нашего сервера | ✅ Да, `forwarder.py`, записи в `forward_log` (status=failed, http=404) |
| UUID передаётся корректно (поле `openRouterWebUiUserId`) | ✅ Да, формат GUID валиден |
| Попытка отправить **email вместо UUID** | ❌ Отклоняется: `The JSON value could not be converted to System.Guid` — поле жёстко типизировано как GUID (ASP.NET), email принять нельзя |
| Ответ на валидный, но незарегистрированный GUID | ❌ 404 «Ключ доступа пользователя не был найден» |
| Сеть/доступность devbim.com | ✅ Сервис отвечает (не сетевая проблема) |

Дополнительная загадка: при тесте с email сервер вернул ещё и
`"request": ["The request field is required."]` — похоже, эндпоинт ожидает
какое-то поле/параметр `request`, о котором нет в текущем контракте.

## 3. Гипотезы (нужна ваша проверка на стороне devbim.com)

1. **Пользователь с UUID `6cce058d-bddf-4c98-96be-bc0494fd32eb` не создан** в
   БД devbim.com (или удалён). Проверить таблицу пользователей по этому GUID.
2. **UUID устарел**: в Open WebUI у пользователя другой
   `openRouterWebUiUserId` (перегенерировался), а на devbim.com остался старый.
   Сверить GUID пользователя в Open WebUI и в БД devbim.com.
3. **Контракт эндпоинта изменился** (см. поле `request` в п.2) — нужен
   актуальный Swagger/описание `PUT /api/OpenRouterModels/updateSubscription`.

## 5. Архитектурный вопрос: перенос сервера на вашу сторону

Возможно, правильнее перенести сервер списания целиком под вашу зону
ответственности (devbim.com), чтобы не зависеть от чужой инфраструктуры.
Для оценки: сервер — это

- **FastAPI-приложение** (этот репозиторий): приём отчётов `POST /api/usage`,
  расчёт кредитов по тарифам (таблица `token_rates`, курсы задаёт GUI),
  пересылка (`forwarder.py`), БД SQLite `credits.db`
  (`usage_records`, `forward_log`, `user_balances`, `token_rates`, `settings`);
- **дашборд аналитики** `/dashboard` (пакет `analytics/`, отдельная SQLite
  `data/analytics.db`);
- **клиенты**: пайпы Open WebUI (`openwebui_pipe_credits.py`,
  `imagerouter_scene_image.py`) шлют отчёты с Bearer-ключом на
  `https://credits.dev-bim.com` (Cloudflare-туннель → localhost:4010).

Варианты:
- **A.** Оставить как есть, вы чините приёмную сторону (минимум работ).
- **B.** Вы поднимаете у себя приёмный эндпоинт по контракту из
  `EXTERNAL_SERVICE_INTEGRATION.md`; мы меняем `FORWARD_URL` в `.env`.
- **C.** Полный перенос сервера списания на devbim.com — тогда клиенты (пайпы)
  переключаются на ваш домен, этот репозиторий передаётся вам.

Ждём решение по варианту A/B/C.

```bash
  -H "Content-Type: application/json" \
  -d '{"openRouterWebUiUserId":"6cce058d-bddf-4c98-96be-bc0494fd32eb","messageCost":0,"modelId":"bytedance/seedream-4.5","modelName":"seedream-4.5","requestText":"","responseText":"","requestDate":"2026-08-18T18:40:00.000000","responseDate":"2026-08-18T18:40:01.000000","isSuccess":true,"errorMessage":null,"metadataJson":"{\"test\":true}"}'

# Email вместо GUID → 400 (поле строго System.Guid)
# (замените значение openRouterWebUiUserId на любой email)
```

Журнал пересылок на нашей стороне: таблица `forward_log` в `credits.db`,
или GUI сервера (кнопка retry для failed), или дашборд вкладка ③.
